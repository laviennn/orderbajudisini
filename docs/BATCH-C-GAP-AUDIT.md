## Security and operational boundaries

- Reuse `withStaff`, `adminResponse`, transaction/identity locks, typed `writeAudit`, and live permission checks. Hidden navigation is never sufficient.
- Preserve database order/payment/inventory constraints and immutable order snapshots. Staff screens must not serialize credential hashes or capability tokens.
- Stock edits remain single-product edits on unlocked draft/active/archived inventory, with existing publication checks; sold/reserved items remain protected.
- Cancellation is only for currently supported unpaid states. Paid refunds, physical returns, carrier API tracking and email invitations have no approved implementation and are not invented.
- No production migrations/deployment. Existing schema appears sufficient; only add migration if implementation reveals a necessary invariant.

3. Promotion management and authoritative preview; quantity visibility/audit.
4. Role-aware dashboard/reporting, responsive/accessibility refinement and documentation.
5. Focused tests per group, then the complete requested validation suite and webpack production build; commit coherent groups, push and prepare PR.
